## Admin Health integration proposal (UI-057 and UI-079)

Use existing AdminRegisterRow index 03, HealthCounts, healthNote and diagnostic field layout. Do not add charts, top-level rows, navigation, schema, requests or provider calls.

- **Confirmed dispatch latency:** existing generationObservability.dispatchLatency supplies windowMinutes (15), sampleSize, truncated, p50Seconds, p95Seconds and source outbox-confirmed-dispatched. Add a small diagnostic group adjacent to Dispatch health. Explicitly label accepted-to-confirmed-dispatch in seconds, not GPU-start, completion, SLA or ETA. Show sample size and bounded/truncated status; null = no data; avoid percentile claims for very small samples (metric alert policy already suppresses p95 alert below 10).
- **Terminal-held reservations:** use terminalHeld.unexpiredByStatus and expiredByStatus for succeeded/failed/cancelled, oldestUnexpiredHeldSeconds, unknownCompletionTime, truncated. Distinguish still-live hold from expired-but-unreleased rows; a truncated count is a lower bound, never a global zero. Unknown completion time is not age zero.
- **Unavailable state:** readGenerationOperatorMetrics returns available=false and null groups on error (generation-operator-store.ts:58–67). Render unavailable separately from true zero; leave other Health groups intact. Do not surface individual job/owner/provider identities, raw diagnostics, or infer an alert when no sample exists.
- **Validation:** pure render/format cases for no data, unavailable, bounded/truncated, small sample, true zero and nonzero holds; configured Admin authorization and two-account scope invariants; responsive desktop/390px and keyboard/reduced-motion checks in separately authorized UI workflow. No new backend needed for this bounded view, and no live fixture is authorized by this audit.
