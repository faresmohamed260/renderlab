# RenderLab — technical claims and evidence

**Verified against:** repository main after the Phase 3 P0 contract merge (2026-11-23). **Purpose:** concise portfolio-facing claim boundaries, not a new capability authority. The [charter](PRODUCT_CHARTER.md) owns direction, [capabilities](architecture/PRODUCT_CAPABILITIES.md) own availability, and [current.json](production/current.json) owns the deployed application SHA. Claims about past verification are dated evidence, not fresh provider probes.

| Claim | Truthful present-day scope | Source / evidence |
| --- | --- | --- |
| **FIBO image generation and reference editing** | Available in closed beta; new requests are **FIBO image only**, not a generic image/video model catalog. | [Request parser](../src/lib/api/generation-contract.ts), [active worker registry](../src/server/generation/worker-fleet.ts), [current capabilities](architecture/PRODUCT_CAPABILITIES.md#current-renderlab-capability). |
| **Masked editing** | Source-preserving FIBO masks restored and independently qualified; not a promise about every future model. | [Phase 1 mask/enforcement release #533](https://github.com/faresmohamed260/renderlab/pull/533), [Phase 1 closeout](history/contracts/architecture/FIBO_BETA_CORRECTNESS_PHASE_1.md). |
| **Invite-only, owner-scoped beta** | Private product access requires active admission, and server authorization checks ownership. Privileged service-role database calls bypass RLS and therefore rely on explicit server-side owner filters. | [Account access](../src/server/account/account-access.ts), [admin MFA authorization](../src/server/admin/admin-auth.ts), [service-role REST client](../src/server/data/supabase-rest.ts), [enforcement release #533](https://github.com/faresmohamed260/renderlab/pull/533). |
| **Browser-independent dispatch** | Server-owned accepted job/outbox and Modal dispatch recovery continue without a submitting browser. **This is not guaranteed unattended finalization.** | [Durable outbox migration](../supabase/migrations/0030_modal_generation_dispatch_outbox.sql), [submit](../src/server/generation/submit-generation.ts), [Architecture ADR-005/006](architecture/ARCHITECTURE_DECISIONS.md). |
| **Owner-return settlement and durable result** | Create/Library/Activity or blocked submit can reconcile a finished job. The H1 correction observes an expired (20-minute) FIBO job's existing provider handle once with short deadlines, recovers any persisting output first, and settles ready or confirmed terminal results normally. Only pending/unconfirmed or undispatched work fails at the deadline; cancellation retains its cancelled edge. Hosted historical proof showed **one Library return → one asset → admission released**; the late-return correction is production-live and verified in [C1](audits/C1_RELEASE_EVIDENCE_2026-11-24.md) ([one no-poll return after 1321s](https://github.com/faresmohamed260/renderlab/actions/runs/45320628441)); this does not guarantee recovery after provider retention expires. Never-returning accounts have no app-side settlement scheduler; dormant results risk reaching provider retention. | [Owner-return code](../src/server/generation/owner-generation-settlement.ts), [hosted proof](https://github.com/faresmohamed260/renderlab/actions/runs/45099617648), [Phase 2 decision](history/contracts/architecture/FIBO_OPERATIONAL_RELIABILITY_PHASE_2_CONTRACT.md). |
| **Retry, cancel, and admission limits** | Supported within active FIBO job lifecycle; not a promise of every possible worker error recovery. | [Cancellation](../src/server/generation/cancel-generation.ts), [admission](../src/server/generation/generation-admission.ts), [reconciliation](../src/server/generation/reconcile-generation.ts). |
| **Durable media management** | Results and uploads persist under owner-scoped media records and server-controlled R2 storage; historical captures may remain even after disposable fixture assets are cleaned. | [Media asset service](../src/server/media/media-assets.ts), [generation persistence](../src/server/generation/native-generation.ts), [media migrations](../supabase/migrations/0002_generation_jobs_media_assets.sql). |
| **Operator signals and alert delivery** | Oldest-active-job versus dispatch health separated; one synthetic gateway-auth email was actually delivered to admin, duplicate burst suppressed and fixture cleaned. | [Operator health](../src/server/observability/oldest-active-job-store.ts), [Phase 2 closeout and evidence](history/contracts/architecture/FIBO_OPERATIONAL_RELIABILITY_PHASE_2_CONTRACT.md). |
| **Protected checks, release and rollback** | Exact-head CI, production read-back and rollback anchor exist. New docs-only commits on main are **not** automatically deployed. | [Protected-check policy](governance/github-protection.json), [release runbook](operations/PRODUCTION_RELEASE_RUNBOOK.md), [production manifest](production/current.json). |
| **Failover** | Historical failover code exists, **but FIBO production currently has one configured worker and no proven live standby/failover pair**. | [Worker fleet](../src/server/generation/worker-fleet.ts), [failover history code](../src/server/generation/native-generation.ts). |
| **Video, Animate, Upscale** | **Retired implementations, no new submissions**. The standalone unauthenticated Upscale worker source is removed; its 410 stub and historical media reads remain. Video remains **planned**, not abandoned. Audio, additional image models, face swap and background removal are likewise not shipped. | [Current parser](../src/lib/api/generation-contract.ts), [upscale 410 route](../src/app/api/media/assets/%5BassetId%5D/upscale/route.ts), [product charter](PRODUCT_CHARTER.md); [video PR #313](https://github.com/faresmohamed260/renderlab/pull/313) was closed unmerged. |
| **Test coverage** | Latest accepted all-source Node-unit read-back was **18.37% lines, 153/212 source files at zero**. These figures **exclude** separate integration, browser, provider-backed and recovery suites; they are not an overall correctness percentage. | [Coverage workflow #45110408755](https://github.com/faresmohamed260/renderlab/actions/runs/45110408755), [coverage verifier](../scripts/verify-unit-coverage-report.mjs). |

**Change rule:** Update a claim only when implementation, active capability registry and exact-source acceptance evidence agree. This sheet is descriptive; it does not authorize a deployment, worker/spend change, model addition, or frontend work.
