**Approved product direction:** 2026-11-18 (owner's FIBO-only workspace instruction and attached implementation plan).

**Repository:** UNMERGED (production workspace implementation).

**Previous bounded model-selection contract:** historical record at `docs/history/contracts/FIBO_MODEL_ROLLOUT_CONTRACT_2026-11-18.md`; its FLUX-default/model-selector scope and exclusion of the Studio workspace are superseded.

## Goal and release boundary

Replace the normal authenticated `/create` with the preserved WANDA FIBO image/edit workspace over current protected `main`. Keep the existing app routing, account controls, durable media, Activity, Library, Viewer and global access model. Preserve the WANDA workspace's desktop/mobile geometry, stage, canvas, glass surfaces, animation and effects, input/keyboard/touch behavior, history and result handling rather than replacing them with a generic composer.

New generation is **FIBO 2.0 image generation and image editing only** through the retained `faresmohamed260` native FIBO gateway and graph. Do not restore FLUX, Qwen image, REDGraft LTX, new video/animation, or upscale. Historical video and media/job records remain readable, without making retired operations eligible for new requests or retry. FIBO's internal Qwen3-VL prompt/VGL assistant is an allowed worker-internal dependency, not a user-selectable model.

The owner intends every preserved image control to work in production. **A visual control does not count as implemented until a verified server/worker contract performs its claimed action.** Any technically unsupported control is an acceptance blocker, not permission to silently ignore it, fake it, re-route to another model, or call this phase complete.

Phase A's bounded production contract merged through PR #422 at `1bcd92f3dc90be2c55d5fd942d23f81a95bff830`; normal implementation is now authorized within the contract, **not** a production/provider change. Phase B/C work is in progress. The first vertical slice adds bounded manual VGL JSON to RenderLab's public FIBO generation request, validates attached image references, persists VGL with the durable job, revalidates it for retry/recipe reconstruction, and forwards JSON to the existing native gateway's already-supported `TextEncodeFibo2` path. Its tests use a fake provider spawn and are not live model qualification. VGL-only jobs persist the supplied JSON in the mandatory nonblank prompt column while submitting an empty plain-text prompt plus VGL to the worker; no schema migration is required.

**Cross-surface regression correction:** FIBO-only Create honors supported account-saved Image geometry; saved legacy Video mode and unsupported Image ratios must not resurrect an invalid Create request. The existing Account Preferences configured test is being updated to assert current FIBO-only Create behavior while keeping historical preference storage and export readable. Historical read-only Viewer comparison remains independent of retired recipe execution eligibility.

**Native mask worker candidate (not product-enabled):** The bounded original implementation now accepts a single-source PNG mask through the private FIBO gateway, stages a binary resized mask in an isolated render, applies the mask to the KSampler latent using stock ComfyUI nodes, and composites the generated region over the unmodified source. On WANDA, the **exact updated native graph** ran against pinned ComfyUI revision `dea870e1a36614b3614c0008a820734d0fecdf4f` at 256x256/one step. The synthetic fixture yielded an unmasked-source mean absolute RGB difference of 0.00 and a masked-region difference of 136.48; details: `docs/audits/FIBO_NATIVE_MASK_PUBLIC_NODE_PROOF_2026-11-18.md`. This qualifies local stock-node feasibility only, not RenderLab owner-scoped mask uploads, hosted Modal execution, full mask geometry or production release. No private Studio source was copied.

**Owner-scoped mask API/persistence implementation candidate:** FIBO generation requests may carry an explicit separately uploaded mask source UUID only with exactly one image input. The existing owner-scoped signed R2 reference-upload ticket/completion path now supports a bounded PNG-only `usage: "fibo-mask"` variant, validates decoded selection and stores a purpose marker in `generation_sources.metadata`. Normal image references cannot reuse a marked mask as an image slot. Job persistence stores a distinct `role: "fibo-mask"` temporary-source entry at the end of `generation_jobs.inputs` so the existing database staging cleanup RPC sees the durable source reference without a migration; reconstruction of failed-job Retry and safe poll reassignment separates it from FIBO image slots, revalidates ownership/readiness, and sends raw PNG bytes only through the private native gateway JSON. Current Create UI does not send or display masks; its saved-recipe path fails closed rather than silently stripping a mask. The isolated helper and PNG validation tests pass; this is not a hosted-signed-in worker end-to-end qualification or production-enabled feature. A new worker deployment and separately approved runtime qualification remain required. **Safety gate:** the normal generation endpoint rejects masked jobs with `generation_disabled` unless the server-only `RENDERLAB_FIBO_MASK_ENABLED=true` setting is explicitly enabled after worker qualification; capability discovery reports `fiboMaskAvailable` only when this gate and native FIBO backend are available. The flag has not been set and must not be used to bypass the release requirements.

**Public-node source-free generated VGL worker candidate:** An original “stock `TextGenerate` → `TextEncodeFibo2`” route (without private WANDA VGL code or additional provider) was successfully executed on the exact pinned local ComfyUI + existing FIBO Edit Turbo checkpoint at 256x256. The worker-only candidate validates bounded text prompts, forbids editing images/manual VGL/mask in this mode, captures and validates the generated JSON, and fails closed on malformed captions. See `docs/audits/FIBO_PUBLIC_NODE_GENERATED_VGL_PROOF_2026-11-18.md`. The subsequent **generated-VGL API/durability implementation candidate** preserves the legacy signed PNG `GET /jobs/{token}` response and adds a separate signed, authenticated `GET /jobs/{token}/vgl` read of the same Modal call result; the Modal renderer returns both the PNG bytes and validated VGL in this mode only. The public RenderLab generation API explicitly validates `autoVgl: true` only for source-free images, stores the mode in `generation_jobs.parameters`, and maps it to private `generate_vgl: true`; it is **default-off** behind server-only `RENDERLAB_FIBO_AUTOVGL_ENABLED=true` until deployment/qualification. The polling server validates the sidecar, persists `generatedVgl` and its provenance **before** transitioning the job to `persisting`, and records it in generated media provenance. Invalid/missing sidecars fail jobs; transient reads have a bounded stale-failure horizon. Safe retries and poll-recovery reconstruct the request, while the old Create recipe screen fails closed until it can display generated VGL. **There is no hosted provider end-to-end qualification or working UI control; no worker or environment flag was deployed.** **Inspiration remains blocked:** two contrasting image fixtures produced identical, incorrect descriptions through stock `TextGenerate.image`; do not enable it or misrepresent normal edit image slots as inspiration. Manual VGL and source-free auto VGL are separate provenance paths.

**Still not completed:** hosted signed-in manual/generated VGL qualification and its full Create UI, production-qualified masking UI/runtime, separate inspiration, multi-output durable batches, live cancellation/partial retries, complete workspace UI parity, staged smoke tests and release. Negative-prompt effectiveness remains unresolved at the existing guidance setting. Do not expose or mark these controls production-functional on the strength of request parsing or local mocks.

**Durable batch domain/schema candidate (2026-11-19):** The public FIBO request domain now validates an optional 2–4 output count while keeping one output as the backward-compatible default. A pending additive `generation_job_outputs` migration defines four owner-bound slot identities, per-slot seed/provider/lifecycle/error/generated-VGL state, deterministic media linkage, active-slot lookup, RLS, browser grant revocation and same-owner job/media enforcement. Retry and server recovery reconstruct the requested count; the current Create recipe loader fails closed rather than reducing a batch to one output. Multi-output admission remains unconditionally disabled until the orchestration/finalization/cancellation implementation and exact migration application are separately reviewed and qualified. The migration is checked in only; it has not been applied to shared Supabase.

**Batch lifecycle core candidate:** Slot creation derives stable wrapped seeds from the job's base seed and inserts all 1–4 owner-bound rows in one database statement. Owner/job/index-scoped read and patch helpers never accept browser/provider routing input. A pure fail-closed aggregate validates exact contiguous slots and derives ordered durable asset IDs plus active, complete, failed, cancelled and partial-completion counts. A terminal mixed batch with at least one durable output is represented as succeeded with an explicit partial summary; zero-output terminal batches remain failed or cancelled. Dispatch, provider polling/finalization and multi-call cancellation are still disabled and must compose this core before admission can be enabled.

**Batch orchestration candidate:** The native FIBO engine now composes that slot core for one accepted job: all durable slots are created before provider dispatch, each call receives its stable slot seed and records its own private worker/call identity, and polling reconciles each slot independently. A completed image enters `persisting` before deterministic R2/media finalization; an interrupted finalization recovers from either the existing media row or the deterministic stored object. Ordered durable asset IDs and a bounded public batch summary are projected onto the parent job without exposing provider identity. One rejected slot does not erase successful siblings, and a mixed terminal batch is truthfully marked as a partial success. This is still an unqualified implementation candidate: multi-call cancellation, failed-slot retry semantics, authorized migration application, browser lifecycle/ZIP UI and provider-backed qualification remain incomplete, so multi-output admission remains unconditionally disabled.

| Masking | Image-edit-only mask, aligned to the selected first/source image, secure upload/validation and **model-influencing** masking; outside-mask preservation verified where promised |
| Batches | 1–4 requested outputs under one owner-scoped durable job with stable output-index identity, partial success, retry semantics, cancellation, recovery and ZIP download |
| Lifecycle | Atomic admission, immutable owner binding, queued/running/partial/completed/failed/cancelled truth, server-owned polling/reconciliation and results persisted before success |
| Session UI | Queue and active progress, history tiles, restoration, result viewer, compare/reuse, saved edits, downloads and keyboard/touch/reduced-motion fidelity |
| Safety | Same-origin mutation protection, media ownership, storage limits, response bounds, secrets server-only, provider IDs hidden from browser |

Implement the request/worker/persistence contracts before enabling their UI paths. Treat manual and generated VGL as different provenance paths; validate the JSON schema against the actual worker schema. No client-supplied provider URLs, gateway keys, output storage IDs or owner IDs.

## Critical technical gates

0. **Text-to-image production parity (not a model-selection blocker):** The owner confirms FIBO 2.0 Edit Turbo already performs source-free text-to-image generation in the running WANDA FIBO Studio. Retain that exact model for both generation and editing. The production task is to reproduce the proven WANDA text-to-image path through the reviewed native graph, authenticated gateway and durable RenderLab lifecycle. Compare the exact checkpoint, graph wiring, prompt handling, settings, and resulting image against the working WANDA path; qualify both source-free generation and editing end to end. Do not substitute FIBO Dev or another model merely because model documentation describes Edit Turbo as editing-focused.
1. **Negative prompt:** Bria's published FIBO Edit Turbo model instructions specify guidance 1 and state that `negative_prompt` has no effect. The native KSampler uses CFG 1. Merely transporting or persisting negative-prompt text is not functional support. Demonstrate effective, model-correct negative conditioning under the retained FIBO contract, or record this as an unresolved acceptance blocker. Do not quietly relabel a positive instruction as independent negative conditioning.
2. **Masks:** The checked-in native ComfyUI `TextEncodeFibo2` graph lacks a mask input. A reviewed public-node and/or original adaptation must prove that masks influence edit generation and that any outside-mask compositing matches the promised result. An overlay-only UI or post-generation crop is not sufficient. Do not copy the two provenance-unverified private WANDA Studio source files.
3. **VGL generation:** Reuse FIBO's internal Qwen3-VL helper only after validating exact supported checkpoint/code/license, input limits, prompt structure and injection boundaries. Manual JSON and generated JSON must produce real worker inputs.
4. **Batch persistence:** Demonstrate crash-safe state for each of up to four output slots, idempotent finalization, partial-failure retries, correct cancellation claims and clean zero/one/multiple-result ZIP assembly. Do not equate four independent browser submissions with one durable production job.
5. **Noncommercial use/provenance:** Preserve Bria attribution and weight notices and the owner-approved invite-only noncommercial boundary. Verify provenance/hosted-use rights for any imported UI asset/source and exact public third-party implementation before use. Avoid private adapter/worker source without a verified grant.
