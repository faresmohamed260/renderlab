## 3. Proposed smallest useful test pyramid

**A. Keep backend and existing required checks intact.** No required-check policy changes. For ordinary UI PRs run `npm run verify:ui-purity` locally or as a small step in existing CI, not a standalone install/build job. A later reviewed PR can attach the step to Engineering Quality after full validation classification; measure its own elapsed time.

**B. Component behavior first.** Add a small dev-only DOM test layer after dependency/license review: React Testing Library, user-event and one compatible DOM implementation with the existing Node runner (or a single dedicated Vitest configuration if TSX/CSS resolution truly requires it). Prefer the existing test runner where feasible; pin exact dependencies and regenerate the lockfile with npm 11, no CDN/runtime test injection. No second general-purpose unit runner merely for convenience. Test production component exports through public props/callbacks and typed API fixtures, not a rewritten clone. Keep real Radix wrappers; mock only fetch/navigation/media/browser APIs at controlled boundaries. Use role/name selectors and user-event, not CSS snapshots or internal state. Start with Create composer interaction, Library selection/actions, alert dialog composition; cover a success, rejection and keyboard cancellation for each. Use fake timers where necessary, assert calls and absence of extra calls, restore globals and avoid shared mutable test state. DOM tests do not prove CSS contrast, real browser focus, canvas, pointer or media behavior.

**C. One optional Playwright Chromium axe smoke.** Keep Playwright already installed; prefer dev-only `@axe-core/playwright` pinned with reviewed lockfile. Scan the actual local Next.js build, not static HTML, cloned markup, Vercel preview or a production URL. First proof: public Landing and signed-out Create/access surface with an explicit expected heading/landmark, HTTP success and no unintended redirect. Next, after a separate reviewed offline UI fixture seam, scan signed-in Create idle and Library confirm dialog; never represent public scans as authenticated workspace coverage. One Chromium project, one worker, desktop and 390px mobile/reduced-motion for one key state; total at most four scans in first increment. Wait for expected state and font/layout readiness; use stable local assets. Run axe WCAG 2.0/2.1/2.2 A/AA tags supported by the pinned engine, report rule/impact/selector/help URL with synthetic data only, fail on violations (not just critical/serious); track incomplete/manual checks separately. If a rule has a proven false positive, narrow the exception to a rule and selector with issue, owner and expiry; do not disable broad regions or globally accept a nonzero baseline. Assert keyboard focus order/visibility, Escape and focus return separately in browser; automated axe is not WCAG conformance, screen-reader testing or a substitute for human review.

**Isolation and cancellation contract.** Optional, non-required workflow on a narrow PR path allowlist (its own workflow/test files, shell/shared primitives and selected Create/Library surfaces, dependencies/config actually affecting them), plus manual dispatch for branch heads; no push/schedule, no environment/secret inputs, no deployment. First proof may use only its own workflow/test path triggers to limit cost. Checkout exact PR head, immutable reviewed actions pins from infrastructure policy, contents: read, checkout persist-credentials: false; Node 24/npm 11 and npm cache. Install locked packages and Chromium only. Build/start on 127.0.0.1 using existing `scripts/start-ci-app.mjs` with bounded readiness; reject configured runtime/service variables, use explicit harmless local fixture configuration only if needed. Block non-loopback browser traffic (including WebSockets/service workers) and server egress during the test phase; fail on attempted external provider requests rather than silently continuing. No Supabase/Auth/R2/Modal/Vercel credentials, real API mutations, hosted fixtures or generations. Offline demo currently imports real backend orchestration with fakes but is explicitly a CLI, not a browser server ([Local Backend Demo](../operations/LOCAL_BACKEND_DEMO.md)); do not invent a login bypass or set production test override flags. Signed-in testing needs a test-only runner/fixture composition outside production routes with fail-closed unknown calls, fixed IDs/clock/data and no runtime auth bypass.

One Ubuntu job, hard `timeout-minutes: 8` (install/build/browser startup included), readiness <= 60s, test timeout <= 30s per state, zero retries by default. PR/ref-scoped concurrency and `cancel-in-progress: true` are safe only because all state lives in a disposable runner: no shared-resource cleanup required. Close browser/context in finally; kill the exact local server process in an always cleanup step/trap; runner destruction is the cancellation fallback. Capture only a compact synthetic failure JSON/screenshot/log, short retention (3 days), no videos/traces by default. Never change the cancellation semantics of configured or worker-backed workflows.

## 4. CI capacity estimate and stop conditions

Use [Actions infrastructure rules](INFRASTRUCTURE.md#github-actions--repository-visibility), [30-day CI audit](../audits/CI_WORKFLOW_COST_AUDIT_2026-11-23.md) and [safe scope change](../audits/CI_P1_04_SAFE_CHANGE_SCOPE_2026-11-24.md). Audit measured about 6,199 weighted runner-equivalent minutes/30 days (historical sampled public-repo billed time zero; not a billing prediction). Historical PR #620 had Quality 51s, Unit Coverage 26s, Portability Linux 49s and Windows 87s. Architecture Markdown is deliberately classified FULL, not evidence-only. Estimates below are marginal runner-minutes, not wall-clock latency, invoices or measured test durations.

| Increment | Estimated job-minutes per applicable head | Hard limit / budget at 20 applicable heads per month |
| --- | --- | --- |
| UI purity within existing Quality | 0.03–0.10 incremental | 0.6–2 min; existing job timeout unchanged |
| 3–6 component behavior cases | 0.1–0.3 per invocation; Quality + coverage + both portability runners may multiply cost | 8–24 raw incremental job-min/month if run four times per head; measure Windows-weighted separately |
| One optional local Chromium smoke | 2–5 total: checkout/setup/npm 0.5–1.5, Chromium 0.5–1.5, build/start 0.7–1.5, scans/cleanup 0.3–0.5 | 8-minute cap; 40–100 min/month expected, <=160 at cap (illustrative, not measured) |
| Automated screenshot baseline matrix | estimated additional 2–5+ per head if independent job, or 0.3–1 for limited captures in existing browser job; review/storage cost extra | defer; no recurring allocation |

At 50 relevant heads smoke would consume ~100–250 job-min/month; at 100, ~200–500. Keep filters conservative; no fleet of per-screen builds, OS/browser matrix, unconditional push duplication or 20x repetition for ordinary UI smoke. After 10 natural runs record real per-job elapsed min/median/p95, cache state, timeout/cancel count, failures and useful defects found; if median >5 min, p95 approaches 8 min, or flaky failures >1 in 10, stop expanding, diagnose and narrow rather than increase limits or rerun blindly. Preserve exact-head acceptance on all required checks; optional smoke success is only evidence for its own assertions. Existing shared-resource jobs may still attach on dependency/source paths; audit trigger changes before merging any lockfile or UI fixture PR.

## 5. Rollout and visual regression decision

1. Review this proposal; maintain the six required contexts and integration-first scope. Requalify retained FIBO-relevant assertions against the live capability **contract**, not production access; remove stale Video/model assumptions only in a dedicated test change.
2. Restore cheap purity checking and add the isolated public two-screen axe proof. Qualify exact head, confirm actual local target, report findings and measured duration; do not auto-fix product UI in the harness PR. Fix genuine violations in separate small feature PRs.
3. Add the first component suites (Create, Library, dialogs), with fixture interfaces reviewed against API contracts. Use the existing offline backend deterministic scenarios for integration data, without introducing a production auth bypass. Extend the same Chromium smoke to one real signed-in fixture route only after isolation is demonstrated.
4. Add risk-weighted Activity and account UI states when changed; retain manual QA/audit workflows under their existing release/fixture authorities, not daily CI. For every UI feature retain responsive rendered verification at approved desktop/narrow widths, touch and reduced motion, human keyboard and screen-reader review for relevant changes ([Design Workflow](../ui/DESIGN_WORKFLOW.md)). Assess focus visibility, 200% zoom/reflow, accessible error association, non-color status, dialog announcements and media/mask interaction separately from axe.

**Visual regression:** defer a full pixel-diff suite. Generated imagery, kinetic transitions, fonts and layout make global baselines noisy; maintaining baselines may cost more than the defects detected during integration-first work. Prefer semantic assertions, fixed synthetic media and bounded desktop/mobile screenshots on failure or a requested rendered review. If repeated stable-shell regressions justify it, add one or two deterministic crops in the same browser job (fixed fonts/viewport/clock, reduced motion, local media, no arbitrary broad masking), review baseline changes separately; no new job or paid service until measured benefit. Keep human design approval separate from test success.

## 6. Risks and acceptance

- False confidence: current unit coverage includes backend and source-based contracts; do not equate it with interactive coverage. Scans of an invite gate do not count as Create composer coverage. Axe cannot certify WCAG 2.2 AA.
- Stale verifiers can encode retired capabilities, old DOM roles, or real provider assumptions. Port assertions one by one to the current product contracts, never weaken semantics to get green.
- Real focus/drag/canvas behavior is underrepresented by DOM mocks. Use browser assertions plus human keyboard/touch/screen-reader review; do not claim a test-only fake proves data isolation.
- CI overrun and cleanup risk: maintain narrow triggers, immutable pins, locked deps, short deadlines and no hosted fixture side effects. On cancellation all state must be runner-local; stop after three failed fix attempts on a check.
- Proof decision for this docs PR: **deferred**, not passed. The inspected offline demo has no rendered app; the existing browser suites depend on configured or production paths, and axe is not in the lockfile. A public-only proof is feasible in the next bounded PR, but its new dependency/lockfile and local network isolation must be qualified together; package changes also affect existing hosted main-push trigger paths. No unpinned install or secret-based shortcut is acceptable. No workflow, dependency, application code, deployment or production state changes in this proposal. Report exact-head required-check results on the PR; a future proof must record exact head, scans actually performed, violation output, job duration, and no external requests before being described as working.
