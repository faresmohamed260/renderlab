## Architecture, data, security and UX constraints

Use existing route owners, UI primitives and semantic tokens, typed capability/recipe/asset/health contracts, server-scoped data loading and maintained focus semantics. No new API endpoints, generation providers, output modes, database schema/migrations, storage changes, secrets, admin permissions, auth bypasses, client-owned durable media state, or provider routing. Preserve same-origin mutation enforcement, session/MFA, account ownership and source validation; never expose raw provider/storage payloads, identifiers in metric labels, or private screenshots. The keyboard mask path emits the existing validated mask contract, not a second persistence pipeline. Reuse supported manual VGL and single-image generation; no manufactured negative conditioning or generated-VGL claim. Never use preview-only behavior as hosted proof.

No Authorized Redesign Mode, aesthetic rebrand, unrelated shell geometry changes, new motion system, new UI capabilities, backend refactoring, or paid monitoring/CI provider. A separate approved change is required if a finding actually needs a capability/backend change. No screenshot-only approval of behavior.
