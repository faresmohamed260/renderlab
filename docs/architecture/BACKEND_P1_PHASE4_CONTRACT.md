The owner retains a private, low-cost friends beta; an independent engineer can validate key architectural and recovery claims without personal tokens.

## Release, migration and rollback rules

1. **No release from contract merge or a source-extraction PR.** Preserve application source vs docs/test-only `main` distinction. A runtime release requires fresh explicit owner authorization, frozen exact SHA, six green protected contexts and a passing exact-SHA **Deployment Readiness** *before* custom-domain cutover.
2. **Staged and reversible:** verify correct Vercel team/project/16-name Production inventory and a same-project READY rollback anchor; stage production with **no automatic domain assignment**, check source and READY, then promote on explicit approval. Re-read exact alias `updatedAt`, app health/capabilities, signed-in Admin aggregate/claims, API error-contract and outbox/reservation health.
3. **If worker/Modal code changes** later, separate explicit production-worker approval, exact app/version history, compatibility matrix, spend ceiling and rollback plan. Do not silently deploy Modal in a web-only release. **No schema migration without approved add/verify/rollback ordering**; old app must tolerate an additive function left installed.
4. **Same sitting:** release record PR updates canonical `docs/production/current.json` and **five mirrors**, protected checks/merge, then passing [Production Documentation Sync](../operations/PRODUCTION_RELEASE_RUNBOOK.md). For each explicitly ordered production release, use the owner-confirmed **single disposable verification fixture**, dispatching the established manual workflow **once**, after live identity and documentation-sync gates; require 202→succeeded, unique durable output, single terminal admission release, second Library idempotence, independent DB/Auth/R2 cleanup and **zero residual active jobs/held reservations/outbox**.
5. **Rollback:** if a real job lifecycle, auth or data regression occurs, restore the pre-qualified READY app alias immediately; re-read target and new cutover time and synchronize the manifest/mirrors. Stop on abnormal provider jobs, double-release, held slots or failed settle **without blind retrial**. An additive verified 0031 RPC can remain installed if previous application does not call it. Destructive SQL rollback and provider/worker downgrade require their own operator authority; do not edit production history to fit a desired state.

## Exit criteria, document outputs and next-phase handoff

Phase 4 closes **only after**:
1. **P1-00 R1–R13 remediation** is dispositioned with verifiable PR and test evidence, no unresolved high-severity lifecycle/auth/CI findings, and any required runtime release separately qualified and recorded.
2. Scoped module decomposition completed with preserved export, call order, failures, R2/index and 0031 atomic semantics, with exact-head proof and appropriate release; no unresolved runtime regressions.
3. One current FIBO provider-only adapter is **actually** routed from the application without duplicate admission, provider calls or settlement; independently characterized fake second-provider seam (not a new enabled model).
4. At least the owner-approved minimal low-cardinality metrics/trace events **implemented and observed** in existing operator read paths (or an explicit documented, owner-accepted scope reduction); show useful queue/provider/release/settle signals without IDs as labels, with alert thresholds tested and no new paid service.
5. CI 30-day budget baseline and safe consolidation measured *before and after*; protected contexts and production verification workflows intact.
6. 0031-aware isolated restore/old-new application compatibility drill with evidence, checksums, owner isolation and 0 residue; no unapproved production restore.
7. Recorded owner decision on never-return settlement (keep with explicit retention/trigger and monitoring, or separately contract a controlled scheduler). **Decision suffices only if evidence/risk acceptance is explicit**, not if silently ignored.
8. **Independent external reviewer** submits a dated evidence-based critique, concrete severity-ranked findings and reproduction links. Owner records fixes or explicit acceptance with rationale; no unresolved **critical** correctness/security/data-loss findings.
9. Owner reviews final **same 12-dimension rubric** honestly and explicitly signs the **backend-first charter gate** before any later frontend phase. Do not infer this sign-off from a passing numeric threshold, merger, design or CI result.
