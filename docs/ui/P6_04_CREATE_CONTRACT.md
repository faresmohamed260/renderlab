## Goal and user value

Turn Create into a coherent, media-first workspace: one place to compose, inspect results, revisit a prompt, and understand and act on real jobs. Desktop has three clear columns; phone feels like a focused app rather than a reduced desktop. Preserve all currently supported creation/editing behavior, account privacy and durable job semantics. Faster perceived loading must not fabricate progress.

4. **History semantics (#712):** This session means since the app opened in this browser tab; preserve across within-tab navigation as appropriate, reset at new tab/app opening, account change/logout; establish explicitly tested lifetime (not a durable store). Prompt history is permanent, account-scoped, searchable across eligible historical prompts including failed/successful attempts; derive from durable owner history where possible, not assets or only the current page; do not introduce destructive clear or a retention change. Specify and test normalization, bounded search and paging across durable history before code. Jobs is chronological account-wide durable projection with older paging, not just recent assets or current session; preserve all eight actual statuses, sanitized errors, valid surviving media access and deleted-result omission UI-067. Queue remains a truthful current-work projection using the same lifecycle source; distinguish local unsent waiting items from accepted jobs. No cross-route polling or global job store. Reuse feature-owned current Queue mechanism where eligible; no speculative header badge.

Preserve user prompt/reference inputs when action fails. Failed Reuse is new: extend owner-scoped reconstruction only after test-first eligibility contract; missing/deleted/foreign references, unsupported legacy mode, mask or autoVgl settings that cannot be truthfully reconstructed must produce explicit unavailable/ineligible state, never silently drop settings. No hidden automatic submit; only explicit Generate/Retry/Run again dispatch. Cancel preserves confirmation, authoritative canCancel, serialized existing lifecycle, pending/error and cancelling→terminal cancelled, no cancel after persisting or terminal; prove pre-dispatch eligibility and races without changing backend claims. Results remain durable and owner-scoped.

Keep current request and idempotency contracts, same-origin mutation guards, worker routing, generation deadlines/terminalization and storage boundaries. Prefer existing server boundary; if lazy search/read requires an endpoint, specify bounded validated query, owner derived from session, private/no-store, sanitized DTO, error mapping, drift and auth registry before approval. Do not overload capability GET /api/generation/jobs. Existing jobs/media are canonical; no new schema or backfill assumed. Search must be server-scoped and bounded; durable prompt-history search must remain inside the no-migration limit. If an index is needed, it becomes a separate owner-approved infrastructure step. Verify actual query feasibility before implementation; do not expose prompts in shared caches or client-wide durable storage.
