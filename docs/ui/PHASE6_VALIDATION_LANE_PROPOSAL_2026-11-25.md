## 2. Shared execution architecture

One path-scoped credential-free Ubuntu lane, initially optional GitHub status, eventually a mandatory *phase acceptance artifact* for relevant UI work (distinct from a protected-main required status). Prefer one npm ci, pinned Chromium install and isolated build shared among browser steps, serial deterministic contexts; isolate performance from simultaneous capture workload. Follow existing pinned actions and least privilege, checkout exact PR head with persist-credentials false where supported, no pull_request_target, no checkout of untrusted external scripts, no secrets, OIDC, cloud services, production cookies or real Auth/DB/R2/Modal fixtures. Restrict network to loopback during browser/build steps; install dependencies/browser before restriction. Browser route interception and blocked service workers complement, not replace, process-level egress isolation; no externally loaded font, imagery, analytics, APIs, server-side fetch or DNS. Assert unexpected outbound attempt fails even when stubbed. Use synthetic assets and stable fixtures, fail closed on unrecognized requests. Host only isolated fixture app or isolated test mount of actual reviewed product components; production build remains credential-free and verifies fixture routes/flags/assets excluded. Never add a production auth bypass to get screenshots. Later route-level parity needs a production-like local build with explicit test-only injection excluded from shipped bundle, not merely mock component performance. Maintain credential-bearing lifecycle workflows unchanged.

Trigger on affected surfaces, shared primitives, token/theme CSS, shell, font/local assets, relevant fixture/capture/build/config/dependency paths; docs-only proposals should not trigger costly browser work. Manual exact-SHA dispatch for evidence refresh; concurrency per PR, cancel superseded runs only because scratch state is reconstructible. No cancellation of shared-resource/provider workflows. One build per lane, do not duplicate current UI shell suite unless measured coverage gap. Publish artifact even after failure; collect independent samples rather than first failure abort; timeout and missing/empty expected artifact are failures. No auto-update snapshots or silently retry until pass. Pin OS image when feasible, browser via lockfile, viewport/DPR=1, locale/timezone, dark color scheme, fonts, synthetic data/clock for static capture only. Recheck OS/browser/font changes as deliberate baseline changes. Never freeze clock or disable motion in performance/kinetic runs. Record exact SHA, approved ref SHA, package lock digest, browser/runner versions, fixture version, viewport/device settings, network profile, motion preference, expected/observed counts, timings, checks, error and artifact digests. Bounded artifact retention 14 days initially; save compact permanent review notes/accepted baseline manifest only, no large disposable videos in Git.

### C. Slow-4G performance (fourth, after stable fixtures and actual UI integration)

**Tools:** existing Playwright Chromium CDP Network.emulateNetworkConditions or supported equivalent plus CPU throttling if explicitly configured, PerformanceObserver for LCP/layout-shift/event timing/long tasks and Navigation/Resource Timing, script input and next-paint marks; no new Lighthouse installation initially. Optional future pinned dev-only web-vitals library if validated Event Timing/session window/INP implementation would otherwise become bespoke or inaccurate; review version, license and offline injection first. No analytics, telemetry export, field collection, provider calls or real uploads. Throttling applies to measured local HTTP requests; route.fulfill/instant mocks can bypass realistic transfer, so serve bounded synthetic bytes/delays via loopback fixture server and verify actual transfer throughput/latency with known payload before recording. Test on optimized production build or clearly label isolated fixture as component-only; development server or static reference HTML is not application performance evidence.

**Proposed reproducible profile:** Slow 4G-like 150ms added RTT/latency setting, 1.6 Mbit/s down, 750 kbit/s up (CDP rates in bytes/s = 200000/93750; log exact CDP semantics and observed transfer, not claim exact measured RTT); CPU 4x slowdown as separate labeled mobile-lab profile, desktop no CPU throttle unless separately chosen. These are proposed settings, not a claim #707 defined those exact settings. Pin Chromium/runner and use single active context. Five fresh cold runs per primary approved surface/profile; fresh context, clear cache/storage, disable service workers, deterministic representative media count/bytes, no fake clock. Warm run via same context only as distinct profile with normal cache; unthrottled baseline and warm comparisons on manual/nightly full lane when approved. No full media transfer benchmarks in PR lane; #707's 1/5/25 MiB upload experiments belong later separate mock I/O suite, never paid calls.

**Measure:** navigate cold direct entry and fixture-controlled transition; register observers before navigation, use buffered entries, record LCP candidate URL/element and time up to first interaction/visibility end; no interaction until defined load observation window, avoid counting placeholder as final content success. If user clicks early LCP finalizes then; keep separate interaction run for shell readiness. CLS standard largest session window (gap under 1s, max 5s), exclude shifts with recent input as metric requires, record shifts and independently assert unexpected shell/skeleton geometry changes. For interaction timing drive real Playwright trusted pointer/key input (not JS dispatchEvent), open composer/menu, advanced/History, Library filter/Viewer when accepted; use Event Timing interactionId and max duration per interaction through next paint, report selected worst/median and sample count. This is lab interaction latency proxy, **not field p75 INP**; missing Event Timing support/entries is incomplete, not zero. Record first recognizable shell, enabled keyboard/pointer shell, acknowledgement, resource waterfall/bytes, long tasks and errors. Avoid trace/video overhead in timed runs; optional separate diagnostic trace on reproduced failure. Avoid hardcoded sleep gating success; fixed measurement window and state markers. Report unsupported metrics or absent content explicitly.

**Targets and distinction from #707:** owner requested LCP <=2.5s, INP <=200ms, CLS <=0.1. #707 defines these as field p75 goals, and separately proposes normal median LCP <=2.5s, Slow-4G cold median <=4s and warm <=2.5s; selected lab interaction median <=200ms, worst of five <=500ms; CLS <=0.1 each run; slow first shell <=2s, usable <=3s, local acknowledgement <=100ms. Keep both thresholds visible, do not falsely claim #707 already mandates 2.5s cold Slow 4G. Proposed stricter Phase 6 design target cold Slow 4G median LCP <=2.5s, lab interaction median <=200ms, CLS <=0.1 every run; explicitly report every sample, worst latency, shell and 4s interim reference. The decision below supersedes this candidate cold-lab threshold; use the initial 4s cold lab budget and ratchet down after repeatable baselines. No silent downgrade. No field INP/p75 verification possible credential-free. Report median plus all five samples, not invented field percentile; compare same fixture/profile baseline and candidate. Initial optional advisory/measurement-only lane, then mandatory evidence for affected surfaces; only calibrated repeatable budgets may become merge-blocking after separate owner approval. Never weaken budgets to fix flake without review.

**Cost:** estimated 3–6 min additional for two initial surfaces, 5 cold runs each, bounded 15–25s observation/interaction per run plus setup; broader normal/warm/route-transition matrix ~6–12 min additional on manual evidence run. Slow 4G real durations depend on asset bytes; cap test time explicitly and report timeout, not discard slow sample. Risks: shared runner CPU, cold cache, emulator settings, synthetic stubs, measurement window, missing Event Timing, screenshot overhead. Isolate timed workload, stable fixture, log CPU/profile and raw values; calibrate noise over at least 5 repeated lane executions before enforcing. Fail structural incompleteness independently of advisory budget status. Do not hide a performance regression as flaky by default.
