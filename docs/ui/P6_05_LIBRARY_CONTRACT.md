# P6-05 — Library workspace and desktop inspector

**Execution scope, 2026-11-25.** This contract defines Library and its contextual desktop inspector. The desktop slice stacks on this docs-only contract for review. The phone proposal needs design and implementation acceptance separately. Production release and provider work require separate authorization.

## Goal and user value

Let members find, inspect and organize saved work without losing their place in the grid. Keep media visually primary and preserve the durable Viewer deep link for full-size inspection and comparison. Reuse real Create continuation and durable media actions, with each action bound to the asset the member is inspecting.

## In scope and sequencing

1. **Desktop composition and inspector.** Use the approved three-panel media-first layout below the existing shell. Left glass panel holds Search, All media, Favorites, Uploads and collection navigation/management. All media is the display label for the existing generated-assets view, with Uploads separate. Favorites composes with the active URL scope as before. Centre holds active view, current-page count, kind filter, Select, sort, grid size and media grid. Grid size only changes desktop density in the mounted view. The glass selection bar anchors near the bottom of the centre column, with space reserved in flow and no focus obstruction. It carries the existing selection/count, page select, Organize, Cancel and Delete actions. Batch Download depicted in the comp has no existing contract. Display counts only when the route supplies them. [Approved Library desktop comp](../../design/approved/2026-11-25-phase6/renders/library-desktop.png)
2. **Contextual selection.** An explicit desktop Inspect control selects an item from the displayed page while the existing card link still opens the canonical Viewer. The optional `inspect` query identifies only the displayed asset and preserves compatible Library navigation state. Other filters and pagination leave the inspector selection behind. Inspection is independent of batch selection and a stale/foreign/off-page ID has no actionable inspector. Keep layout stable with a clear unselected panel state. Swap selected media immediately, make the active card distinguishable without color and keep keyboard focus on the activating control. Keep inspector actions in logical DOM order with an explicit Viewer link.
3. **Inspector detail and actions.** Show actual preview and available display name, prompt, creation date, dimensions and media type. Anchor Create actions below context. Show Open in Create with an Edit image label for the existing image handoff. Both labels describe the same action because Create has one supported media-source entry point. Reuse settings is secondary and only appears after the same server-side recipe validation used by Viewer, scoped to the selected current-page item. Inspecting alone does no mutation or generation. Reuse Viewer Favorite, signed-product Download, Rename and confirmed Delete. Keep successful inspector deletion within the current Library view and clear the deleted item from inspection with a meaningful focus fallback. Collection membership and Source Fold remain in the full Viewer. Show optional fields only when the current DTO can support them.
4. **Phone proposal for a later slice.** Keep the shared logo-opened navigation sidebar and no bottom tabs. Use a single media grid with search, sort and selection within reach. Group source, type and collections into a shared Sheet when space is constrained. Open the inspector from an explicit item action in a separate shared Sheet with contained scroll and Done/Escape, return focus to the item or surviving grid controls, and keep the Viewer deep link. Respect safe areas, keyboard and reflow. Prototype discovery and inspector sheets with the existing state owners before coding. The approved set contains no Library phone comp.
5. **Loading.** Keep available shell, heading and stable control geometry. Use the shared Skeleton only in unresolved content regions when an auth-safe loading boundary is available. Match grid/preview geometry, expose real busy state and render bounded shimmer with static Reduce Motion. Empty, sign-in, unavailable, failed and loaded content replace placeholders. No fake focus targets or job-progress claims. Slice 1 preserves existing route loading boundaries.

## Explicitly out of scope

Phone implementation, full Viewer layout changes, batch Download, new filters, fabricated totals or metadata, shortcuts that have no existing contract, new Create actions or generation modes, Activity changes, new endpoints, migrations, dependencies, shared component changes, provider access, spend and deployment.

## Architecture, data and dependencies

Keep Next.js routes, server URL parsing and React 19 transient UI state. Keep the existing stable chronological sort and offset reset, normalized literal search and opaque media IDs. Read recipe eligibility only for the requested visible item using the current owner and Viewer’s existing resolver. Render only its validated recipe ID. Reuse existing same-origin endpoints and Viewer controls. Keep Library uploads in the current picker/drop path, and keep selection page-scoped through refresh, pruning and partial failures. Source from installed UI primitives under UI-026, V2 semantic tokens and named spring roles. Use the snappy role for immediate selection feedback and its static equivalent under reduced motion. Keep header and phone navigation owned by the shell. [Design Language V2](DESIGN_LANGUAGE_V2.md)

## Security and ownership

Keep verified account identity, admission, existing origin/mutation guards, owner-filtered reads, tombstone-first deletion and RLS unchanged. An opaque inspection ID cannot select data outside the current owner list. Never expose storage identifiers, raw provider data, signed object URLs as durable links or client-owned authorization. Download naming, rename fields, upload transfer, deletion recovery and deleted-result visibility retain the existing contracts.
