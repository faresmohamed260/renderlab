# One-shot dispatcher PostgreSQL TLS canary (qualification only)

This read-only probe is stacked on security PR #603. It shares the **same production gateway image**, `dispatch_supabase.SupabaseDispatchStore` connection path, psycopg/CA system installation, Modal environment forwarding, and existing dispatcher-only Modal secret. The temporary canary app is independent of the production gateway and has no HTTP endpoint, schedule, GPU, background task, provider call, job claim or database mutation.

## Worker 1 runbook (explicit qualification step; do not run during CI)

1. After reviewing the stacked PR, check out **its exact qualified head SHA** using the approved deployment workstation/workflow. Ensure Modal is authenticated to the **existing approved workspace** and that the target is the **same Modal environment** as the intended production dispatcher. Record the SHA and environment *name*, not credentials.
2. Provide the four **resource-name variables** that the existing `workload_runtime_env` already requires: `RENDERLAB_MODAL_ENVIRONMENT`, `RENDERLAB_MODAL_DISPATCHER_SECRET`, `RENDERLAB_MODAL_GATEWAY_SECRET`, `RENDERLAB_MODAL_MONITOR_SECRET`. These are Modal resource identifiers, not the credentials. Never echo the underlying secret, DB URL, CA contents or environment dump.
3. From repository root run `modal run --env "$RENDERLAB_MODAL_ENVIRONMENT" workers/fibo-studio/dispatcher_tls_canary.py`. The probe creates an independent, ephemeral `renderlab-dispatcher-tls-canary` app with **0.25 CPU and 45-second execution timeout** and uses the **existing dispatcher secret** only. It does not deploy or modify `renderlab-generation-gateway`.
4. Require exit code 0 with precisely `PASS dispatcher_tls_verify_full_select_1` as the canary's own result. Any `FAIL dispatcher_tls_...` is a release blocker. Capture only the sanitized result, SHA, environment name, and time in the audit; do not paste raw Modal/libpq errors or credential-bearing logs into GitHub.
5. On failure, leave #603 out of release batch A, investigate the CA/root chain and configured **pooler hostname**, or restore the previously qualified gateway image. Do not fall back to `sslmode=require`, update any secret, or change a database configuration to make the test pass without separate approval.

The probe checks that the system or explicitly configured CA file exists *before* using the store's connection path, so the dispatcher's documented `sslmode=require` fallback **cannot falsely pass** the canary. The only SQL is `select 1 as probe_ok`. A pass establishes that the live Modal environment can complete an authenticated TLS read-only round trip with the configured dispatcher DB identity; it does **not** establish dispatch privileges, migration compatibility, provider availability, or permission to deploy production runtime changes. Local CI uses mocks only; the live execution is **worker-1-owned** and has not been performed by worker 4.
